2. CÓMO USAR CADA ALGORITMO
===========================

BUBBLE SORT:
```cpp
OrdenamientoDirecto::BubbleSort(arr, n);
```
Cuándo: Muy pocas situaciones, casi nunca en producción
Ventaja: Muy simple de entender
Desventaja: Muy lento para datos grandes

INSERTION SORT:
```cpp
OrdenamientoDirecto::InsertionSort(arr, n);
```
Cuándo: Arrays pequeños, datos parcialmente ordenados
Ventaja: Rápido en datos casi ordenados, adaptativo
Desventaja: O(n²) en peor caso

SELECTION SORT:
```cpp
OrdenamientoDirecto::SelectionSort(arr, n);
```
Cuándo: Necesitas minimizar intercambios
Ventaja: Número garantizado de intercambios = O(n)
Desventaja: Siempre O(n²) comparaciones

SHELL SORT:
```cpp
OrdenamientoLogaritmico::ShellSort(arr, n);
```
Cuándo: Buena relación entre velocidad y complejidad de código
Ventaja: Más rápido que directos, más simple que Quick/Heap
Desventaja: No estable

QUICK SORT:
```cpp
OrdenamientoLogaritmico::QuickSort(arr, n);
```
Cuándo: Necesitas velocidad general (por defecto en std::sort)
Ventaja: Muy rápido en promedio, in-place
Desventaja: O(n²) peor caso (raro en práctica)

HEAP SORT:
```cpp
OrdenamientoLogaritmico::HeapSort(arr, n);
```
Cuándo: Necesitas garantía O(n log n) siempre
Ventaja: Rendimiento consistente, in-place
Desventaja: Menos eficiente en caché que Quick Sort

BUSQUEDA SECUENCIAL:
```cpp
int pos = Busqueda::BusquedaSecuencial(arr, n, objetivo);
if (pos != -1) // Encontrado en posición pos
```
Cuándo: Array desordenado
Ventaja: Funciona con cualquier array
Desventaja: Lento para arrays grandes

BUSQUEDA BINARIA:
```cpp
// REQUIERE: array ordenado
int pos = Busqueda::BusquedaBinaria(arr, n, objetivo);
if (pos != -1) // Encontrado en posición pos
```
Cuándo: Array ordenado
Ventaja: O(log n) muy rápido
Desventaja: Array debe estar ordenado primero

ARBOL BUSQUEDA BINARIA:
```cpp
Busqueda::ArbolBusquedaBinaria<int> arbol;
arbol.Insertar(valor);
if (arbol.Buscar(valor)) // true si existe
arbol.RecorridoInorden(); // Imprime en orden
```
Cuándo: Inserciones/búsquedas dinámicas frecuentes
Ventaja: Mantiene datos ordenados dinámicamente
Desventaja: O(n) peor caso si desbalanceado


3. DECISION RAPIDA
==================

¿Necesitas ordenar?
?? ¿Datos pequeños (<100)?
?  ?? Usa Insertion Sort (muy rápido, simple)
?? ¿Datos parcialmente ordenados?
?  ?? Usa Insertion Sort
?? ¿Datos muy grandes (>100000)?
?  ?? Usa Quick Sort (generalmente el mejor)
?? ¿Necesitas garantía O(n log n) siempre?
?  ?? Usa Heap Sort
?? ¿Propósito educativo?
   ?? Comienza con Bubble Sort, avanza con otros

¿Necesitas buscar?
?? ¿Array desordenado?
?  ?? Búsqueda Secuencial
?? ¿Array ordenado?
?  ?? Búsqueda Binaria (mucho más rápido)
?? ¿Inserciones/eliminaciones frecuentes?
?  ?? Árbol de Búsqueda Binaria
?? ¿Muchas búsquedas?
   ?? Ordena primero, luego usa Búsqueda Binaria


4. EJEMPLOS DE CODIGO
=====================

Ordenar y buscar:
```cpp
const int n = 100;
int arr[n];
Utilidades::GenerarArrayAleatorio(arr, n);

// Ordenar
OrdenamientoLogaritmico::QuickSort(arr, n);

// Buscar
int objetivo = 42;
int posicion = Busqueda::BusquedaBinaria(arr, n, objetivo);
```

Usar Árbol de Búsqueda:
```cpp
Busqueda::ArbolBusquedaBinaria<int> arbol;

// Insertar valores
arbol.Insertar(50);
arbol.Insertar(30);
arbol.Insertar(70);
arbol.Insertar(20);

// Buscar
if (arbol.Buscar(30)) {
    cout << "30 encontrado en el árbol" << endl;
}

// Mostrar en orden
cout << "Árbol en orden: ";
arbol.RecorridoInorden();
cout << endl;
```

Comparar algoritmos:
```cpp
int arr1[n], arr2[n], arr3[n];
Utilidades::CopiarArray(arrOriginal, arr1, n);
Utilidades::CopiarArray(arrOriginal, arr2, n);
Utilidades::CopiarArray(arrOriginal, arr3, n);

// Usar diferentes algoritmos en copias
OrdenamientoDirecto::InsertionSort(arr1, n);
OrdenamientoLogaritmico::ShellSort(arr2, n);
OrdenamientoLogaritmico::QuickSort(arr3, n);

// Verificar todos están ordenados
assert(Utilidades::EstaOrdenado(arr1, n));
assert(Utilidades::EstaOrdenado(arr2, n));
assert(Utilidades::EstaOrdenado(arr3, n));
```


5. REGLAS IMPORTANTES
====================

? Bubble Sort: Más de 100 elementos = NUNCA
? Búsqueda Binaria: REQUIERE array ordenado
? Árbol Búsqueda: Puede degenerarse si está desbalanceado
? Quick Sort: Elige pivote aleatorio para mejores resultados
? Heap Sort: Garantizado O(n log n) siempre
? Shell Sort: Usa gap = n/2, n/4, ..., 1


6. NOTACION BIG O - GUIA RAPIDA
================================

O(1)   = Constante (inmediato)
O(log n) = Logarítmica (muy rápido) - ejm: Búsqueda Binaria
O(n)   = Lineal (rápido)
O(n log n) = Linearítmica (buena) - ejm: Quick Sort
O(n²)  = Cuadrática (lento) - ejm: Bubble Sort
O(2?)  = Exponencial (muy lento)
O(n!)  = Factorial (extremadamente lento)

Ejemplo práctico:
n = 1,000,000

O(log n)      ? 20 operaciones
O(n)          ? 1,000,000 operaciones
O(n log n)    ? 20,000,000 operaciones
O(n²)         ? 1,000,000,000,000 operaciones
O(2?)         = números enormes (imposible)

9. TIPS DE RENDIMIENTO
======================

1. Para conjuntos pequeños: Insertion Sort
2. Para conjuntos medianos: Shell Sort
3. Para conjuntos grandes: Quick Sort
4. Si necesitas garantía: Heap Sort
5. Siempre ordena antes de usar Búsqueda Binaria
6. Usa Árbol para muchas búsquedas/inserciones dinámicas
7. Copia el array si necesitas conservar el original


10. PARA RECORDAR
=================

Directos: Bubble, Insertion, Selection
- Todos O(n²) en promedio
- Simple pero lento
- Útiles para enseñanza

Logarítmicos: Shell, Quick, Heap
- O(n log n) o mejor en promedio
- Más complejo pero mucho más rápido
- Usados en producción

Búsqueda:
- Secuencial: O(n) siempre
- Binaria: O(log n) pero requiere orden
- Árbol: O(log n) promedio, dinámico
